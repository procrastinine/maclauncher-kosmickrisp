# Cached Poly Layer replay

The cached Poly Layer replay interface reuses the existing producer and raster pair. A draw's original vertex, tessellation and geometry work, transform feedback and pre-raster statistics execute once. The final hardware vertex program reads the prepared output, rejects primitives outside the selected logical layer before fragment execution and writes native render-target index zero. Fragment Layer reads retain the selected logical layer.

Inside `kk_draw_one_view`, after its first resolved `kk_flush_gfx_state` and before predicates, uploads or producer stages, attachment binding code registers `kk_poly_layer_replay_begin` with the original draw command, logical layer count and binding callback. Begin updates the existing cached-pair selection and per-draw upload mask without executing producer work. The initial physical slice and its clear/load/store state are bound before native encoder creation. The callback binds matching color, depth/stencil and resolve slices and preserves clear, load, store and resume behavior. It returns `VkResult`; an error becomes the command-buffer error. `kk_poly_layer_replay_end` restores ordinary selection and clears the selector binding. Registration requires paired cleanup on every exit from the original draw preparation. Callback data remains valid through end during command encoding; GPU selector uploads retain the command buffer’s normal submission lifetime. A producer that does not write Layer draws logical layer zero once; the render path still clears every requested layer.

Cached addresses and indirect counts retain their existing Poly layouts and command-buffer uploader/heap lifetime. Replay completes inside the original draw before the next producer or command-heap reset. The callback does not dispatch user stages, issue another Vulkan draw or retain a cache across command executions.

An active replay uses a nullable `constant uint2 *` at the dedicated `KK_ARGUMENT_POLY_LAYER_REPLAY` argument-table entry, immediately after the existing interlock entry. The two words are `logical_layer` at offset zero and `enabled` at offset four; host assertions bind the layout and the 31-buffer Metal limit. Every layer receives its own immutable eight-byte selector while retaining the original per-draw and captured geometry addresses. A null pointer selects ordinary behavior and is tested before any selector load. Ordinary per-draw declarations and upload extents are unchanged. The normal graphics table and indirect graphics commands declare the new entry and initialize it to null; all previous entry indices remain unchanged.

The Poly registration interface accepts vertex, tessellation and geometry pipelines. Multiview retains the original mask and executes producer work once for each selected view. A view's cached raster draw selects only that view's attachment slice, writes physical render-target index zero and preserves the actual view index for fragment and input reads. Noncontiguous view masks retain their original indices. An absent application Layer output means relative layer zero within each view; the framebuffer slice is the view index. Non-multiview Layer output retains its independent original layer selection. Mesh retains its canonical output packet interface. Additional cached-reader compilation for Layer output or multiview uses temporary NIR freed at pipeline creation.

The existing outer per-view loop owns view multiplicity; attachment binding code does not add another view loop. Registration occurs with its current one-bit mask. Multiview initialization and attachment bounds use selected view indices, since Vulkan's rendering layer count may be one even when a higher view bit is selected. The original native VS alternative retains its amplification lowering; only the cached sibling reads the existing per-draw multiview index. Ordinary per-draw declarations and upload extents are unchanged.

The interface does not implement active alias replay for GPU-generated command buffers or independent final-stage linkage without the complete producer capture layout. Attachment callers supply those respective command and final-link integrations.

Cached raster pipelines retain their actual primitive class. Original points use native point primitives; Bresenham line readers use native lines; expanded rectangular/smooth lines, polygon points and fill use triangles. The class is preserved in serialized producer metadata, native descriptors and attachment-specialization keys, including dynamic line-mode changes.

Layered point-output geometry uses the raster-only retained point reader. It reads the ordered point packets and existing indirect count produced by the common capture, clip and prefix path. Original geometry work, transform feedback and pre-raster queries execute once per original view; all layer readers finish before a subsequent draw can reuse the capture heap. Native point size, position, Layer, viewport, clipping and other captured outputs retain their original values.
