# Sampler minimum and maximum filtering

MacLauncher KosmicKrisp provides `VK_EXT_sampler_filter_minmax` and the Vulkan 1.2 `samplerFilterMinmax` feature. A sampler with `VK_SAMPLER_REDUCTION_MODE_MIN` or `VK_SAMPLER_REDUCTION_MODE_MAX` returns the componentwise minimum or maximum of the texels with nonzero weights in its filter footprint. Weighted-average samplers continue to use Metal sampling. Enabling the original extension also supports Vulkan 1.1 devices without a Vulkan 1.2 feature structure.

Apple GPU family 10 and later use native Metal sampler reduction. On earlier GPUs, shared sampling helpers select the mip levels and reduce samples at texel centers. Linear filtering includes each contributing texel, while linear mip filtering combines the contributing levels. Sampler LOD bias and clamps, image-view minimum LOD, addressing, and borders apply before reduction. LOD queries retain the requested sampler's bias, clamps and mipmap mode. A custom border color participates as a texel value. Image component mapping also applies to the returned components, including constant zero and one mappings.

On the emulated path, every format already exposed for sampled images also exposes `VK_FORMAT_FEATURE_2_SAMPLED_IMAGE_FILTER_MINMAX_BIT`. This includes integer, normalized, floating-point, sRGB, compressed and depth formats. Native reduction retains the native format-filter capability boundary.

The [shared shader cache key](KOSMICKRISP_SHADER_CACHE.md) distinguishes sampler reduction from pipeline statistics. The sampled-image descriptor remains 64 bytes. Reduction mode, filter selection and address metadata occupy existing padding, alongside the mipmap and LOD metadata shared with compute derivative queries. Devices that do not enable `samplerFilterMinmax` do not run the reduction lowering. Immutable weighted-average sampler bindings also omit it. Mutable sampler bindings on an enabled device select the operation from descriptor contents, including when a sampler is created after its pipeline. Repeated operations with the same sampling form share a helper within the shader. Reduction and border reconstruction use the same path, and implicit derivatives are evaluated before sampler-dependent dispatch.

Depth formats support reduction with comparison disabled. Vulkan requires weighted-average reduction when sampler comparison or YCbCr conversion is enabled. Sparse samples combine the residency codes of the contributing taps with bitwise OR.

The implementation uses Mesa NIR and Metal texture operations. Native reduction follows the same Metal capability boundary as [MoltenVK](https://github.com/KhronosGroup/MoltenVK); the centered-sample technique is also used by [MetalSharp's SPIRV-Cross adaptation](https://github.com/metalsharp/VKD3D-Proton-MacOS). The [Vulkan sampler reduction specification](https://docs.vulkan.org/refpages/latest/refpages/source/VkSamplerReductionMode.html) defines the reduction modes.
